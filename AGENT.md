# AGENT.md — контекст проекта для будущих агентов/чатов

> Этот файл объясняет текущее состояние проекта. Читай его перед изменениями.

## Что это

MoneyTracker — личный Telegram-бот для учёта расходов в путешествиях. Пользователь
пишет трату текстом (`Ресторан Plov 4500 тенге`, `Такси 1200`) или отправляет фото
чека с подписью. Бот записывает расход в Excel, считает итоги и ведёт кошелёк.

Фото чеков **не распознаются**. Фото только сохраняются в папку чеков; расход создаётся
из текста сообщения или подписи к фото. Не возвращай Gemini vision без явного запроса.

Язык общения с пользователем — **русский**, стиль короткий и понятный для первого запуска.

## Как сейчас запущено

Бот работает в облаке на **Railway** (always-on, 24/7). Локально на Маке он больше не
крутится — переезд завершён.
- Хостинг: Railway, сборка через Nixpacks по `Procfile` (`worker: python bot.py`) и
  `.python-version` (3.13).
- Режим: long polling.
- Логи: дашборд Railway (Deploy logs), а не локальный `bot.log`.

После изменения кода **деплой = commit + push в `main`.** Railway подключён к GitHub-репозиторию
и авто-деплоит каждый push в `main`, пересобирая образ. Никаких `launchctl` и ручного
перезапуска больше нет:

```bash
git add -A
git commit -m "..."
git push origin main   # дальше Railway сам пересоберёт и перезапустит
```

Живые данные лежат на Railway Volume, смонтированном в `/data` (env на Railway:
`EXCEL_PATH=/data/expenses.xlsx`, `SETTINGS_PATH=/data/settings.json`). Volume обязателен:
без него таблица и настройки стирались бы при каждом редеплое. Локальные `expenses.xlsx` и
`settings.json` в репозитории — **устаревший снимок до переезда**, на живого бота не влияют.
Чтобы посмотреть или починить живые данные, иди через самого бота (`/excel` и т.п.) или через
Volume, а не через локальные файлы.

Один Telegram-токен обслуживает только один процесс. Локальный LaunchAgent
`com.moneytracker.bot` выгружен (`launchctl unload`), локального процесса нет; plist ещё лежит
на диске, но не загружен. Не запускай вручную `python bot.py`, пока бот крутится на Railway:
будет ошибка 409.

Файлы `DEPLOY.md`, `moneytracker.service`, `deploy_push.sh` описывают **другой** путь деплоя
(Oracle Cloud + systemd), который в итоге не выбрали — переехали на Railway. Поэтому они
остаются неиспользуемыми. Не удаляй их без отдельного запроса.

## Стек

- Python 3.13, venv в `.venv/`
- `python-telegram-bot==21.6` (async)
- `google-genai` → Gemini `gemini-2.5-flash` только как fallback для сложного текста
- `openpyxl` — Excel
- `httpx` — курсы валют
- `python-dotenv` — `.env`

## Главные файлы

| Файл | Назначение |
|---|---|
| `bot.py` | Telegram-хендлеры, команды, кнопки, меню |
| `expense_parser.py` | Локальный парсер простых трат |
| `receipt_analyzer.py` | Gemini fallback: текст → JSON `{date, description, amount, currency, category}` |
| `excel_store.py` | Excel, итоги, кошелёк, профили, стабильные ID |
| `currency.py` | Курсы валют, конвертация, парсинг сумм |
| `settings.py` | `settings.json`: владелец, валюта по умолчанию, профили |
| `bills.py` | Сохранение и выдача фото чеков |
| `config.py` | `.env`, валюты, категории, пути |

Не трогай без явного запроса: `.env`, `expenses.xlsx`, `settings.json`, `bot.log`,
`bills/`, `expenses_backup_*.xlsx`.

## Возможности

- Текстовая запись трат: `Ресторан Plov 4500 тенге`, `Такси 1200`, `Заправка 30 долларов`.
- Фото с подписью: фото сохраняется, трата записывается из подписи.
- Фото без подписи: только сохраняется в чеки.
- Под каждой тратой есть кнопки: категории, правка суммы, правка описания, удаление.
- `/total [период]`: `сегодня`, `неделя`, `месяц`, `год`, `N` дней.
- `/wallet`, `/add 5000 USD`: кошелёк.
- `/startbalance` (или кнопка «✏️ Исправить начальный баланс» под `/wallet`): переписать
  начальный баланс активного профиля; пополнения и обмены не трогает.
- Реальный обмен: `поменял 67 долларов 5360 сом`. Первая сумма списывается, вторая зачисляется.
- `/profiles`: туры. Каждый тур (профиль) — отдельный `.xlsx`-файл, имя файла = имя тура.
- `/currency`: валюта по умолчанию, когда в тексте нет явной валюты.
- `/excel`: выгрузка файла активного тура.
- `/bills`: скрытая команда, отдаёт сохранённые фото чеков.
- `/undo` (`/delete`): удалить последнюю трату.
- `/clear`: очистить последние сообщения в чате.

Удалённые возможности не возвращать без явного запроса: `/csv`, `/convert`,
распознавание фото чеков через Gemini vision.

## Парсинг трат

Путь по умолчанию — local-first:
1. `expense_parser.parse_expense()` разбирает простые сообщения с одной суммой.
2. Если текст неоднозначный, с датой или несколькими числами, бот вызывает
   `receipt_analyzer.analyze()` как Gemini fallback.
3. Если суммы нет или сумма ≤ 0, трата не записывается.

Валюта:
- явная валюта из текста имеет приоритет;
- если валюты нет, используется `settings.default_currency`;
- дефолт — KZT.

Категории фиксированные: `Отель`, `Питание`, `Бензин`, `Прочее`.

## Excel

- **Файл на тур.** Каждый тур (профиль) — отдельный `.xlsx` в `config.DATA_DIR`
  (= папка `EXCEL_PATH`, на Railway том `/data`). Имя файла = имя тура; реестр
  `settings.json`: `profiles[name] = {"file": ...}`, активный тур → активный файл
  (`excel_store._active_path()`). У всех файлов одинаковые листы-константы
  `Расходы` / `Итоги` / `Кошелёк`.
- Лист расходов: Дата | Описание | Сумма | Валюта | Категория | Сумма USD | ID.
- ID скрыт и стабилен. Кнопки используют ID, не номер строки.
- Лист итогов пересчитывается готовыми числами, без Excel-формул.
- Кошелёк хранится отдельным листом движений: старт, пополнение, обмен.
- Начальный баланс — это строки «Старт» («Начальный баланс») на листе кошелька. Их
  переписывает `excel_store.set_start_balance` (читает `get_start_balance`), не трогая
  пополнения и обмены.
- Сохранение атомарное: `_atomic_save(wb, path)` пишет temp-файл и делает `os.replace`.
- `create_profile` создаёт новый файл тура; присланный `.xlsx` импортируется как тур по
  имени файла (`import_profile_from_upload`). `migrate_to_files()` — разовый переход со
  старой однофайловой схемы (листы на тур) на файл-на-тур; идемпотентен, бэкапит старый
  `expenses.xlsx`. Не возвращай однофайловую схему без явного запроса.

Не заменяй стабильные ID на номера строк и не меняй атомарную запись на прямой
`wb.save(EXCEL_PATH)`.

## Доступ

Бот личный. `_auth_gate` стоит в `group=-1` и останавливает чужие апдейты.
Если `ALLOWED_USER_IDS` задан — доступ по списку. Если не задан — первый
пользователь становится владельцем (`settings.owner_id`). Сверх этого владелец
может выдать доступ другим через `/allow <id>` (хранится в `settings.json`, ключ
`allowed_user_ids`); `/disallow` убирает, `/allowed` показывает список. Управлять
доступом может только владелец/`.env`-список (`_is_admin`) — гости, добавленные
через `/allow`, не могут; id из `.env` и владельца через `/disallow` не снять.
Заблокированному `_auth_gate` показывает его Telegram-id, чтобы он попросил доступ.

## Важные решения

1. Gemini модель: `gemini-2.5-flash`, не `gemini-2.0-flash`.
2. Thinking отключён: `ThinkingConfig(thinking_budget=0)`, `max_output_tokens=1024`.
3. Дефолтная валюта — KZT.
4. `httpx` logger держать на WARNING: иначе в лог может попасть URL `getUpdates` с токеном.
5. `on_error` глушит сетевые ошибки без трейсбека, остальные логирует.
6. Запись траты с суммой ≤ 0 запрещена (`_NoAmount`).
