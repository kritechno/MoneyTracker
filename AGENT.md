# AGENT.md — контекст проекта для будущих агентов/чатов

> Этот файл объясняет, что это за проект, как он устроен и какие решения уже приняты.
> Читай его перед тем, как что-то менять.

## Что это

Telegram-бот для учёта личных трат в путешествиях. Пользователь шлёт боту **фото чека**
(с подписью или без) или **текст** («Ресторан Plov 4500 тенге»). Бот через **Gemini (vision)**
распознаёт трату, умно категоризирует и записывает в **Excel-файл** с итогами.
Пользователь в основном в Казахстане/Центральной Азии — валюты KZT, KGS, USD.

Язык общения с пользователем — **русский**.

## Как сейчас задеплоено (ВАЖНО)

Бот работает **локально на Маке пользователя** через **macOS LaunchAgent**:
- Label: `com.moneytracker.bot`
- Plist: `~/Library/LaunchAgents/com.moneytracker.bot.plist` (копия — `com.moneytracker.bot.plist` в репо)
- Запускается при входе в систему, перезапускается при сбое (`KeepAlive`), логи в `bot.log`.

**Режим работы — long polling.** Telegram хранит сообщения боту до 24 часов, поэтому пока
Мак выключен/спит, сообщения копятся и обрабатываются по порядку, когда Мак снова онлайн.
Ограничение: если Мак выключен >24ч, старые сообщения теряются.

> Обсуждали переезд в облако (Oracle Cloud Always Free) — файлы для этого готовы
> (`DEPLOY.md`, `moneytracker.service`, `deploy_push.sh`), НО пользователь решил **пока остаться
> на Маке**. Облачные файлы не используются, но пусть лежат.

### Управление ботом на Маке
```bash
PLIST="$HOME/Library/LaunchAgents/com.moneytracker.bot.plist"
launchctl unload "$PLIST"   # остановить
launchctl load "$PLIST"     # запустить
# после правок кода — перезапуск: unload && load
launchctl list | grep moneytracker   # статус (PID, exit-code)
tail -n 20 bot.log                    # логи
```
**После любого изменения кода нужно перезапустить LaunchAgent**, иначе работает старая версия.

> ⚠️ Один Telegram-токен — только один работающий бот. Нельзя запускать вторую копию
> (например, вручную `python bot.py`, пока крутится LaunchAgent) — будет ошибка 409.

## Возможности и команды

- 📸 Фото чека → распознавание; ✍️ текст тоже работает.
- Под каждой тратой — инлайн-кнопки: 4 категории + ✏️ Сумма / ✏️ Описание + 🗑 Удалить.
  Правка суммы/описания — через `awaiting_edit` в `user_data` (следующее сообщение = новое значение).
- `/start`, `/help` — инструкции
- `/total [период]` — сводка; период: `сегодня`/`неделя`/`месяц`/`год`/`N` дней (фильтр в `compute_totals(since=...)`)
- `/undo` (=`/delete`) — удалить последнюю трату
- `/currency` — выбрать валюту по умолчанию (KZT/KGS/USD) кнопками
- `/excel` — прислать `expenses.xlsx`; `/csv` — экспорт активного профиля в CSV
- `/clear` — спрашивает подтверждение, затем удаляет ~200 последних сообщений в чате

## Доступ (владелец)

Бот личный: хендлеры проходят через `_auth_gate` (group=-1). Доступ только владельцу.
Если `ALLOWED_USER_IDS` (в `.env`) задан — по нему; иначе первый написавший «занимает»
бота (`settings.owner_id`, auto-claim). Чужим — отказ + `ApplicationHandlerStop`.
- `/convert` / «конвертация …»:
  - 2 суммы («конвертация 30 долларов 15000 тенге») = **проверка обменника**: отдал → получил,
    сравнение с рыночным курсом, выгодно/невыгодно + %.
  - 1 сумма = пересчёт в другие валюты по рынку.
- Меню команд регистрируется при старте (`set_my_commands` в `_post_init`).

## Категории и валюты

- **Категории:** Отель, Питание, Бензин, Прочее. Ресторан/кафе → категория **Питание**,
  описание в формате `Ресторан «Название»` (без перечисления блюд; если названия нет — `Ресторан`).
- **Валюты:** KZT (тенге), KGS (сом), USD (доллар). Конвертация в USD по живому курсу
  (open.er-api.com, с офлайн-фолбэком в `currency.py`).

## Структура Excel

- Лист **«Расходы»**: Дата | Описание | Сумма | Валюта | Категория | Сумма USD | **ID (скрыт)**
  ID — стабильный идентификатор траты (см. грабли №8). Кнопки под тратой кодируют ID,
  а не номер строки, поэтому удаление/правка не «съезжают» после сдвига строк.
- Лист **«Итоги»** пересчитывается готовыми числами (без формул Excel):
  остаток кошелька, суммы по каждой валюте, всего в USD, суммы по категориям.
- `excel_store._rebuild_summary()` пересоздаёт лист «Итоги» при каждой записи/правке.
- Запись на диск — **атомарная** (`_atomic_save`: temp-файл + `os.replace`), чтобы сон/
  перезапуск Мака не оставил битый `.xlsx`.

## Важные решения и грабли (не наступай повторно)

1. **Модель Gemini = `gemini-2.5-flash`, НЕ `gemini-2.0-flash`.**
   У `2.0-flash` в регионе пользователя free-tier квота = 0 (ошибка 429 limit:0).
   `2.5-flash` / `2.5-flash-lite` / `flash-latest` — работают бесплатно.
2. **Thinking отключён** (`ThinkingConfig(thinking_budget=0)`) и `max_output_tokens=1024`.
   Иначе у 2.5 «мышление» съедает лимит токенов и ответ обрывается на `{` → фото не распознаётся.
3. **Валюта по умолчанию = KZT** (а не USD!). Раньше дефолт был USD, и крупные тенговые суммы
   (вода 10500, ресторан 62600) записывались как доллары. Дефолт хранится в `settings.json`,
   меняется через `/currency`, передаётся в `receipt_analyzer.analyze(..., default_currency)`.
   Приоритет: явная валюта на чеке/в подписи > дефолт.
4. **Подпись пользователя имеет приоритет** над содержимым чека (зашито в промпт).
5. **Не запускать вторую копию бота** (см. выше про 409).
6. Курсы валют кэшируются на 1 час (`currency.py`).
7. Ответ Gemini парсится как JSON (`response_mime_type="application/json"` + `_extract_json`
   на случай обёрток).
8. **Идентичность трат — по стабильному ID, не по номеру строки.** Раньше кнопки кодировали
   номер строки; после удаления средней траты строки сдвигались и кнопки указывали на чужую
   трату. Теперь скрытый столбец ID; resolve через `_find_row_by_id`. Старые записи получают
   ID при миграции `ensure_ids_setup()` (в `_post_init`).
9. **httpx-логгер приглушён до WARNING** — иначе INFO писал полный URL `getUpdates` с токеном
   бота в `bot.log` и спамил его. Не возвращай уровень обратно.
10. **Глобальный `add_error_handler`** (`on_error`): сетевые ошибки (сон Мака) → WARNING без
    трейсбека, остальные логируются и пользователю шлётся «что-то пошло не так».
11. Запись Excel атомарна (`_atomic_save`). Не заменяй на прямой `wb.save(EXCEL_PATH)`.
12. Запись траты пропускается при сумме ≤ 0 (`_NoAmount`) — чтобы текст без суммы не плодил мусор.

## Как вносить изменения

1. Правишь код.
2. Быстрая проверка: `cd <project> && source .venv/bin/activate && python3 -c "import bot"`.
   Логику можно проверять модульно (например `currency.parse_amounts`, `excel_store.compute_totals`),
   передавая `EXCEL_PATH=/tmp/test.xlsx` чтобы не трогать боевые данные.
3. Перезапусти LaunchAgent (unload && load), проверь `bot.log` на `Application started`.
4. Тестовое распознавание реальных фото проверить нельзя без картинки — для проверки vision
   можно генерировать тестовый чек через PIL.
